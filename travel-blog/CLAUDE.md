# CLAUDE.md — 여행 블로그 메이커

이 파일은 Claude(AI)가 `travel-blog/` 폴더에서 작업할 때 따르는 가이드입니다.

## 프로젝트 개요

여행 후 사용자가 적은 메모(간 곳, 먹은 것, 비용, 느낀 점)를 **블로그 글 초안**으로 정리해 주는 웹사이트입니다.
서버·빌드 없이 정적 파일만으로 동작합니다. 기능과 로드맵은 `README.md`를 기준으로 합니다.

- 이 앱의 코드는 모두 `travel-blog/` 폴더 안에 둡니다.
- 저장소 루트의 `index.html`(버킷리스트), `memo/`(메모 앱), `instatoon/`(꼼쥐툰)은 **요청이 없으면 수정하지 마세요.**

## 원칙

1. **빌드 도구·프레임워크 금지** — React, Vue, npm 번들러, TypeScript를 도입하지 않습니다. 순수 HTML/CSS/JavaScript만 사용합니다.
2. **외부 라이브러리 금지** — CDN 포함 어떠한 외부 라이브러리도 사용하지 않습니다. 필요한 기능은 직접 구현합니다.
3. **파일 분리 필수** — HTML, CSS, JavaScript는 반드시 별도 파일로 작성합니다. `<style>` 태그나 `<script>` 인라인 코드는 작성하지 않습니다.
4. **기존 기능 보존** — 요청받지 않은 기존 기능은 임의로 삭제하거나 변경하지 않습니다. 수정 시 요청받은 범위만 변경합니다.
5. **단순하게** — 사용자는 웹 개발을 배우는 중입니다. 짧고 읽기 쉬운 코드, 명확한 이름을 우선합니다.
6. **한국어** — UI 문구, 주석, 커밋 메시지 본문은 한국어로 작성합니다. (변수·함수 이름은 영어)
7. **지어내지 않기** — 초안·요청문에 사용자가 입력하지 않은 장소·가격·평가·일화를 채워 넣지 않습니다. 빈 칸은 `[입력 필요]`로 표시합니다.

## 코드 구조

만들 예정인 파일:

| 파일 | 역할 |
| --- | --- |
| `index.html` | 마크업 뼈대, CSS/JS 불러오기 |
| `css/base.css` | CSS 변수(색상·간격·폰트), 리셋, 다크 모드 |
| `css/layout.css` | 단계 탭 / 본문 배치, 반응형 |
| `css/form.css` | 입력칸, 일정 카드, 버튼, 결과 화면 |
| `js/fields.js` | 기본 정보 질문 목록(제목·설명·예시), 빈 여행 데이터 |
| `js/days.js` | 일정 카드 편집 (추가·삭제·순서 변경) |
| `js/styles.js` | 글 스타일(후기형·정보형·감성형)과 말투 규칙 문구 |
| `js/prompt.js` | 여행 데이터 + 스타일 → AI 요청문 (순수 함수) |
| `js/draft.js` | 여행 데이터 + 스타일 → 템플릿 초안 마크다운 (순수 함수) |
| `js/store.js` | 데이터 계층. `localStorage` 읽기/쓰기는 **이 파일에서만** |
| `js/app.js` | 진입점. 상태를 들고 각 모듈을 연결 |

- 스타일·말투 규칙 문구는 `styles.js` 한 곳에만 둡니다. 다른 파일에서 같은 문구를 다시 쓰지 않습니다.
- 새 기능은 가능하면 기존 파일에 맞춰 넣고, 파일이 너무 커질 때만(약 300줄 이상) 분리합니다.
- `prompt.js`, `draft.js`는 나중에 테스트를 붙이기 쉽도록 **DOM에 의존하지 않게** 작성합니다.

## 데이터 모델

```js
// localStorage 키: "travel-blog-draft"
{
  version: 1,
  trip: {
    place: "오사카",
    startDate: "2026-10-01",   // "YYYY-MM-DD"
    endDate: "2026-10-04",
    companions: "친구 2명",
    purpose: "",               // 여행 목적 / 한 줄 소감
    days: [
      {
        id: "d_<timestamp>",
        label: "1일차",         // 날짜 또는 장소 이름
        places: "",             // 간 곳
        food: "",               // 먹은 것
        cost: "",               // 비용 메모 (사용자가 쓴 그대로)
        transport: "",          // 이동 방법
        good: "",               // 좋았던 점
        bad: "",                // 아쉬웠던 점
        photos: ""              // 넣고 싶은 사진 메모
      }
    ],
    style: "review",           // "review"(후기형) | "info"(정보형) | "essay"(감성형)
    tone: "polite"             // "polite"(해요체) | "casual"(반말) | "plain"(문어체)
  }
}
// 테마: localStorage 키 "travel-blog-theme" ("light" | "dark")
```

- 데이터 형식을 바꾸면 `version`을 올리고 `store.js`에 마이그레이션을 추가해 **기존 입력이 사라지지 않게** 합니다.

## 글 조립 규칙

- **요청문(`prompt.js`)**: 스타일 규칙 → 말투 규칙 → "지어내지 말 것" 규칙 → 여행 기본 정보 → 일정별 메모 순서로 이어 붙입니다.
  빈 칸은 `(입력 없음 — 지어내지 말고 [입력 필요]로 표시)`로 바꿉니다.
- **템플릿 초안(`draft.js`)**: 제목 후보 → 도입부 → 일정별 본문 → 비용 정리 → 꿀팁 → 마무리 순서의 마크다운입니다.
  사용자가 쓴 문장을 그대로 쓰고, 연결 문장만 스타일·말투에 맞게 붙입니다.
- 비용은 사용자가 적은 값만 씁니다. 합계 계산은 숫자로 적힌 값만 더하고, 계산할 수 없으면 합계를 표시하지 않습니다.

## 디자인 가이드

- 여행 느낌의 밝고 가벼운 화면: 아이보리 배경, 하늘색 계열 강조색 하나.
- 테두리보다 배경색 차이로 영역을 나눕니다.
- 색상·간격은 `base.css`의 CSS 변수로만 지정하고, 하드코딩하지 않습니다.
- 다크 모드: `@media (prefers-color-scheme: dark)` + `[data-theme="dark"]`로 수동 전환 지원.
- 본문 폰트 크기는 16px 이상 (아이폰 Safari 입력 시 자동 확대 방지).
- 모바일(약 768px 이하)에서는 한 번에 한 단계만 보이고, 이전/다음 버튼으로 이동합니다.
- 버튼에는 `aria-label`, 키보드로도 모든 기능을 쓸 수 있게 합니다.

## 보안

- 사용자가 입력한 문구를 화면에 넣을 때는 항상 `textContent`를 사용합니다. `innerHTML`에 사용자 텍스트를 넣지 않습니다.
- API 키 등 비밀 값은 저장소에 커밋하지 않습니다. (3차 목표 AI 연동은 방식이 정해진 뒤 진행)

## 실행 & 확인

```bash
python3 -m http.server 8000   # 저장소 루트에서 → http://localhost:8000/travel-blog/
```

자동 테스트는 아직 없습니다. 변경 후에는 다음을 직접 확인합니다.

- [ ] 입력 → 새로고침해도 남아 있는가
- [ ] 일정 카드 추가·삭제·순서 변경이 동작하는가
- [ ] 스타일·말투를 바꾸면 요청문과 초안이 바뀌는가
- [ ] 빈 칸이 `[입력 필요]`로 표시되고, 입력하지 않은 내용이 들어가지 않는가
- [ ] 복사 버튼이 동작하는가
- [ ] 다크 모드와 모바일 폭(375px)에서 레이아웃이 깨지지 않는가
- [ ] 브라우저 콘솔에 에러가 없는가
