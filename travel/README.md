# ✈️ 여행 파트너스 글 메이커

여행 제휴(파트너스) 수익형 글을 쓰기 위한 **입력 폼 + 글 초안 작성** 웹사이트입니다.
**공통 정보 폼 + 카테고리별 상세 폼**에 실제 경험과 현재 조건을 입력하면,
독자가 **결제 직전에 궁금해하는 포인트**를 중심으로 블로그 글 초안을 만들어 줍니다.

> 광고 문구를 찍어내는 도구가 아닙니다.
> "직접 써봤는지 / 현재 가격·조건이 맞는지 / 누구에게 맞는지"를 꼭 입력받아,
> **예약 직전 독자에게 진짜 도움이 되는 글**을 만드는 것이 목표입니다.

---

## 💡 왜 폼을 나누나요?

카테고리마다 독자가 결제 전에 궁금한 것이 다릅니다. 한 폼으로 뭉치면 입력이 애매해지고, 글도 얕은 광고문이 됩니다.

| 카테고리 | 독자가 결제 전에 제일 궁금한 것 |
| --- | --- |
| eSIM | 내 폰에서 잘 터지고, 진짜 데이터가 충분한가? |
| 숙소 | 이 가격에 위치·객실·시설이 실제로 괜찮은가? |
| 투어·액티비티 | 일정에 넣을 가치가 있고, 취소·안전 리스크는 없는가? |
| 여행 패키지 | 광고 가격 말고 최종적으로 얼마가 드는가? |
| 교통패스 | 내 동선에서 개별 결제보다 정말 이득인가? |

이 핵심 질문은 글의 **도입부 질문**과 **결론**에 그대로 쓰입니다.

## ✨ 주요 기능

### 1차 목표 (MVP) — AI 없이 동작
1. **공통 정보 폼** — 모든 여행 글에 공통으로 받는 항목 (아래 [입력 폼 명세](#-입력-폼-명세))
2. **카테고리 선택** — eSIM / 숙소 / 투어·액티비티 / 여행 패키지 / 교통패스
3. **카테고리별 상세 폼** — 카테고리마다 다른 질문과 "특히 유의할 점" 안내
4. **작성일 기준 확인** — 가격·운영시간·혜택·무료 취소 조건처럼 **바뀌는 정보**는
   "작성일 기준으로 다시 확인했어요" 체크와 확인 날짜를 받습니다.
   확인하지 않은 항목은 글에 `[작성일 기준 확인 필요]`로 표시됩니다.
5. **자동 검토** — 글 만들기 전에 위험한 표현과 빠진 정보를 경고합니다.
   - 단정 표현: "최저가", "무제한", "누구나 가능", "모든 폰에서 됨", "노쇼핑" 등
   - 빠진 필수 정보: 직접 이용 여부, 추천·비추천 대상, 숨은 비용, 취소 규정 등
   - 제휴 링크가 있는데 경제적 이해관계 표시 문구가 없을 때
6. **카테고리별 계산 도우미**
   - 교통패스: 개별 결제 합계 vs 패스 가격 → **몇 번 타야 본전인지**, 절약/손해 금액
   - 여행 패키지: 광고가 + 유류할증료 + 가이드팁 + 선택관광 + 싱글차지 → **실제 1인 총액**
   - 숙소: 객실가 + 세금 + 리조트피 + 도시세 + 조식·주차 → **1박 실제 가격**
7. **글 초안 만들기** — 카테고리별 글 구조에 입력 내용을 채워 마크다운 초안을 만들고 **복사**합니다.
   - 맨 위: 제휴 표시 문구 + "○○○○년 ○월 ○일 기준" 안내
   - 앞쪽: 핵심 질문에 대한 짧은 답, 숨은 비용·주의사항
   - 본문: 실제 경험, 비교, 계산 결과
   - 끝: 추천 / 비추천 대상, 선택한 CTA
8. **자동 저장** — 작성 중인 글은 브라우저(`localStorage`)에 자동 저장되어 새로고침해도 남습니다.

### 2차 목표
- **Claude 요청문 만들기** — 입력값 + 작성 규칙을 합쳐 claude.ai에 붙여 넣을 요청문 생성
- **Claude 자동 작성** — claude.ai 링크로 열었을 때 버튼 하나로 글 초안 받기 (API 키 불필요)
- 여러 글 저장·불러오기, 글 목록 (카테고리·작성일별)
- 같은 여행의 공통 정보를 다른 카테고리 글에 **재사용** (예: 오사카 여행 → 숙소 글 + 교통패스 글)
- 제목 후보·메타 설명·소제목(H2) 추천
- 내보내기/가져오기 (`.md`, `.json`)

### 3차 목표 (결정 필요)
- **업데이트 알림** — 작성일이 오래된 글에 "가격·조건 다시 확인" 표시
- 플랫폼별 글 형식 (네이버 블로그 / 티스토리 / 워드프레스)

## 📋 입력 폼 명세

### 공통 입력 항목 (모든 여행 글)

| 항목 | 입력 방식 | 메모 |
| --- | --- | --- |
| 글 목적 | 선택: 검색 유입 / 제휴 전환 / 실제 후기 / 비교 정보 | 글 구조가 달라짐 |
| 메인 키워드 · 서브 키워드 | 텍스트 (서브는 여러 개) | |
| 여행지 · 여행 시기 · 인원 · 여행 스타일 | 텍스트 / 선택 | 스타일 예: 가족, 부모님 동반, 신혼, 혼자, 친구 |
| 직접 이용 여부 | 선택: 직접 이용 / 이용 안 함(정보 정리) | **이용 안 함이면 후기 표현을 쓰지 않음** |
| 실제 경험 | 긴 글 | |
| 실제 결제 금액 · 이용일 | 숫자 + 날짜 | 🔄 바뀌는 정보 |
| 제휴 링크 · 할인코드 · 쿠폰 | 텍스트 | 🔄 바뀌는 정보, 링크가 있으면 제휴 표시 필수 |
| 독자가 가장 궁금해할 한 가지 | 텍스트 | 기본값은 카테고리 핵심 질문 |
| 추천 대상 / 비추천 대상 | 각각 목록 | **둘 다 필수** |
| 꼭 넣을 사진·영상·캡처 | 목록 | 글 안에 `[사진: ○○]` 자리로 표시 |
| CTA | 선택: 가격 조회 / 할인 확인 / 예약하기 / 댓글 유도 | |
| 작성일(확인일) | 날짜 | 기본값은 오늘 |

> 🔄 표시는 **작성일 기준으로 다시 확인해야 하는 정보**입니다. 예전 여행 경험만으로 현재 조건을 단정하면 글 신뢰도가 바로 떨어집니다.

### 1. eSIM

**받는 내용**
- 국가·도시 / 이용 기간
- 구매한 eSIM 상품명 · 통신망 · 데이터 용량
- 가격 🔄 / 할인코드 · 제휴 혜택 🔄
- 무제한 여부, 일일 제공량 이후 속도 제한 (예: 하루 2GB 후 384kbps)
- 설치 시점: 출국 전 설치 / 현지 개통
- 개통 방식: QR / 앱 / 수동 입력
- 테더링 가능 여부
- 전화번호 · SMS 수신 가능 여부
- 실제 속도와 끊김 여부
- 공항 · 호텔 · 관광지별 체감 신호
- 사용 기기 (아이폰 / 갤럭시 등, 모델명)
- 설치 · 개통에서 막힌 부분
- 기존 유심 · 로밍과 비교한 이유
- 실제로 해 본 것: 유튜브 / 지도 / 카카오톡 / 테더링 (체크)
- 추천 · 비추천 대상

**특히 유의할 점 (폼 안내 + 자동 검토)**
- "무제한" 문구를 그대로 쓰지 않기 → 일일 몇 GB 뒤 저속 전환인지 꼭 입력
- 기종 · 통신사 잠금 · 듀얼심 설정에 따라 문제가 생길 수 있음 → "모든 폰에서 된다" 금지
- 현지에서 QR을 다시 열어야 하는 상품도 있음 → **설치 전 QR 캡처 / 메일 보관 팁** 넣기
- "빨랐어요"보다 유튜브 · 지도 · 카카오톡 · 테더링이 됐는지가 설득력 있음
- 추천 CTA: "여행 직전 공항에서 급하게 사지 말고 가격 먼저 확인하기"

### 2. 숙소

**받는 내용**
- 숙소명 / 정확한 위치 / 공항 · 역 · 관광지 접근성 (도보 · 택시 몇 분)
- 숙박일 · 인원 · 객실 타입
- 실제 결제 가격 🔄 / 세금 · 리조트피 · 보증금 포함 여부
- 예약 플랫폼별 비교 가격 🔄 (플랫폼 · 가격 · 확인일 표)
- 예약 당시 쓴 쿠폰 · 회원 혜택
- 객실 구조: 침실 · 욕실 · 침대 · 거실 · 주방
- 체크인 · 체크아웃 시간 🔄 / 얼리체크인 가능 여부
- 실제 룸 컨디션: 청결, 소음, 뷰, 침구, 수압, 냄새 (항목별 평가)
- 어메니티와 비치 여부
- 부대시설: 수영장 · 사우나 · 조식 · 주차 · 짐보관 등
- 부대시설 운영시간 🔄 · 예약 필요 여부 · 추가 비용
- 아쉬웠던 점
- 추천 대상 / 피해야 할 여행객
- 예약 링크 CTA

**특히 유의할 점**
- **최저가 단정 금지** → 날짜 · 환율 · 회원등급에 따라 달라지므로 "내 예약일 기준"으로 쓰기
- 객실 사진은 **공식 사진 / 실제 사진** 구분 (사진 목록에서 선택)
- 리조트피 · 도시세 · 조식 별도 · 주차비 같은 **숨은 비용은 글 앞쪽에**
- 위치는 "좋아요"가 아니라 `역 도보 몇 분 / 공항 택시 몇 분 / 주요 관광지까지 이동 시간`으로

### 3. 투어 · 액티비티

**받는 내용**
- 투어명 / 운영사 / 예약 플랫폼
- 이용일 · 시작 시간 · 총 소요 시간
- 인원 · 실제 결제 금액 🔄 · 할인코드 🔄
- 포함 사항 / 불포함 사항 (장비 · 팁 · 입장료 · 식사 · 사진 추가 구매 체크)
- 집결 장소와 이동 난이도
- 픽업 여부 · 픽업 지역 · 추가 비용
- 준비물 / 복장 / 보관함 · 탈의실 여부
- 날씨 영향 · 취소 기준 · 환불 규정 🔄
- 실제 일정 흐름과 대기 시간 (시간표)
- 가이드 · 안전 관리 · 언어 지원
- 사진 촬영 · 장비 대여 · 식사 포함 여부
- 제한사항: 체력 난이도 / 멀미 / 수영 가능 여부 / 연령 / 임산부
- 직접 느낀 하이라이트와 아쉬운 점
- 추천 대상 / 비추천 대상

**특히 유의할 점**
- "누구나 가능" 금지 → **수영 실력, 연령, 임산부 제한, 멀미, 체력 난이도**를 명확히
- 사진이 예쁘다는 말만 쓰면 광고 같아짐 → 이동 시간 · 대기 · 화장실 · 젖은 옷 처리 같은 현실 정보
- 날씨 취소 시 환불 · 일정 변경 기준은 결제 전 불안을 줄이는 핵심 정보
- 포함 사항은 꼭 분해 → 장비, 팁, 입장료, 식사, 사진 추가 구매가 별도일 수 있음
- 추천 CTA: "일정 확정 전 마감 여부와 픽업 가능 지역부터 확인"

### 4. 여행 패키지

폼 첫 줄에서 **유형부터** 고릅니다: 항공+호텔 / 자유여행 패키지 / 세미패키지 / 패키지여행

**받는 내용**
- 패키지 유형
- 여행사 · 상품명 · 출발일 · 여행 기간
- 출발지 · 항공편 · 수하물 조건
- 인원 · 총 결제 금액 🔄 / 1인당 금액
- 포함 · 불포함 내역
- 추가 비용: 선택관광 · 가이드팁 · 유류할증료 · 싱글차지 등 🔄
- 호텔명 · 객실 구성 · 식사 제공 여부
- 필수 쇼핑 · 자유시간 · 일정 강도
- 항공 · 호텔 확정 시점 (출발 임박 확정 여부)
- 현지 가이드 · 인솔자 만족도
- 실제 일정과 상품 설명의 차이
- 자유여행 대비 절약 또는 손해 본 지점
- 취소 · 변경 수수료 조건 🔄
- 추천 대상 / 비추천 대상
- 예약 전 체크할 항목

**특히 유의할 점**
- **광고 최저가만 쓰면 안 됨** → 유류할증료, 팁, 옵션, 쇼핑, 1인 객실 추가비까지 합산한 실제 가격
- "노쇼핑" "자유여행" 같은 표현은 상품 상세 조건을 다시 확인하고 쓰기
- 항공 · 호텔이 출발 임박 시 확정되는 상품은 확정 시점을 적기
- 부모님 동반이면 일정 강도 · 이동시간, 신혼여행이면 호텔 · 자유시간 비중을 따로 평가
- 비교 기준: `일정 자유도 / 숨은 비용 / 숙소 / 이동 피로도` (가격 하나만 보지 않기)

### 5. 교통패스

**받는 내용**
- 국가 · 도시 / 패스 이름
- 종류: 철도 · 지하철 · 버스 · 공항 이동 · 관광패스
- 가격 🔄 / 구매처 / 할인코드 🔄
- 유효 기간과 사용 시간 기준: **구매일 기준 / 첫 사용일 기준 / 24시간제 / 달력일**
- 사용 가능 노선 · 불가 노선 (공항철도 · 특급열차 · 지정석 · 사철 체크)
- 실물 교환 필요 여부 / 수령 장소 · 운영시간 🔄
- 방식: 앱 / QR / 실물권
- 실제 이용 기록: 날짜 · 구간 · 개별 요금 (표로 입력)
- 카드 · 현금 · 개별권 대비 손익 계산 (자동)
- 좌석 지정 · 예약 필요 여부
- 공항 도착 직후 사용 가능 여부
- 분실 · 환불 · 변경 규정 🔄
- 여행 동선

**특히 유의할 점**
- "싸다"가 아니라 **몇 번 타야 본전인지** 계산해서 보여 주기
- 유효기간이 '구매일 기준'인지 '첫 사용일 기준'인지 꼭 구분
- 공항철도, 특급열차, 지정석, 사철은 제외인 경우가 많음 → 가장 중요한 정보
- 동선이 느슨하면 패스가 오히려 손해 → **비추천 대상 필수**
- 실물 교환이 필요하면 공항 줄, 수령 장소, 운영시간까지

## 🛠 기술 스택

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 화면 | HTML + CSS (Flexbox/Grid, CSS 변수) | 빌드 없이 바로 열림 |
| 동작 | 순수 JavaScript (ES Modules) | 프레임워크 학습 부담 없음 |
| 저장 | `localStorage` | 서버 없이 브라우저에 저장 |
| 실행 | 내 컴퓨터 (`python3 -m http.server`) | 무료, 설치할 것 없음 |

## 📁 폴더 구조 (예정)

```
my-page/
└── travel/
    ├── index.html          # 진입점
    ├── README.md
    ├── CLAUDE.md           # AI 작업 가이드
    ├── css/
    │   ├── base.css        # 색상 변수, 폰트, 리셋, 다크 모드
    │   ├── layout.css      # 머리말 / 단계 탭 / 본문 배치, 반응형
    │   ├── form.css        # 입력칸, 카드, 표 입력, 경고 상자
    │   └── result.css      # 글 초안 미리보기, 복사 버튼
    └── js/
        ├── categories.js   # 카테고리 5종: 핵심 질문, 유의할 점, 금지 표현, 글 구조
        ├── fields.js       # 공통 폼 + 카테고리별 폼 질문 목록, 빈 폼, 진행률
        ├── form.js         # fields.js를 보고 입력칸을 그림
        ├── calc.js         # 본전 계산, 실제 총액 계산 (순수 함수)
        ├── checks.js       # 자동 검토: 단정 표현, 빠진 정보, 확인 안 된 변동 정보 (순수 함수)
        ├── writer.js       # 입력 → 마크다운 글 초안 (순수 함수)
        ├── result.js       # 검토 결과 + 초안 미리보기 + 복사 화면
        ├── store.js        # localStorage 저장/불러오기
        └── app.js          # 진입점, 화면 연결
```

## 🚀 실행 방법

빌드 과정이 없습니다. JavaScript 모듈 때문에 파일을 더블클릭하는 대신 간단한 로컬 서버로 여세요.

```bash
cd ~/Documents/my-page
git pull                      # 최신 변경 받아오기
python3 -m http.server 8000   # 서버 켜기 (끌 때는 Ctrl + C)
# 브라우저에서 http://localhost:8000/travel/ 열기
```

> 입력한 내용은 그 브라우저에만 저장됩니다. 중요한 글은 복사해서 따로 보관하세요.
