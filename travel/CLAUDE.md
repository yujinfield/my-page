# CLAUDE.md — 여행 파트너스 글 메이커

이 파일은 Claude(AI)가 `travel/` 폴더에서 작업할 때 따르는 가이드입니다.

## 프로젝트 개요

여행 제휴(파트너스) 수익형 글을 쓰는 웹사이트입니다.
**공통 정보 폼 + 카테고리별 상세 폼**(eSIM / 숙소 / 투어·액티비티 / 여행 패키지 / 교통패스)으로 실제 경험과 현재 조건을 입력받아,
독자가 **결제 직전에 궁금해하는 포인트** 중심의 마크다운 글 초안을 만들어 줍니다.
서버·빌드 없이 정적 파일만으로 동작하며, 사용자는 내 컴퓨터에서 `python3 -m http.server`로 열어 씁니다.
기능, 입력 항목, 로드맵은 `README.md`를 기준으로 합니다. **입력 폼 명세는 `README.md`의 "입력 폼 명세"가 원본입니다.**

- 이 앱의 코드는 모두 `travel/` 폴더 안에 둡니다.
- 저장소 루트의 `index.html`(버킷리스트), `memo/`(메모 앱), `instatoon/`(꼼쥐툰 메이커)는 **요청이 없으면 수정하지 마세요.**

## 원칙

1. **빌드 도구·프레임워크 금지** — React, Vue, npm 번들러, TypeScript를 도입하지 않습니다. 순수 HTML/CSS/JavaScript만 사용합니다.
2. **외부 라이브러리 금지** — CDN 포함 어떠한 외부 라이브러리도 사용하지 않습니다. 필요한 기능은 직접 구현합니다.
3. **파일 분리 필수** — HTML, CSS, JavaScript는 반드시 별도 파일로 작성합니다. `<style>` 태그나 `<script>` 인라인 코드는 작성하지 않습니다.
4. **기존 기능 보존** — 요청받지 않은 기존 기능은 임의로 삭제하거나 변경하지 않습니다. 수정 시 요청받은 범위만 변경합니다.
5. **단순하게** — 사용자는 웹 개발을 배우는 중입니다. 짧고 읽기 쉬운 코드, 명확한 이름을 우선합니다.
6. **한국어** — UI 문구, 주석, 커밋 메시지 본문은 한국어로 작성합니다. (변수·함수 이름은 영어)
7. **지어내지 않기** — 글 초안에 사용자가 입력하지 않은 경험·가격·시간·수치를 채워 넣지 않습니다. 빈 칸은 `[입력 필요]`로 표시합니다.

## 글 작성 규칙 (사이트가 만드는 글에 항상 적용)

이 규칙은 코드에서 `js/categories.js`(카테고리별)와 `js/writer.js`(공통) 상수로만 둡니다. 같은 문구를 여러 파일에 다시 쓰지 않습니다.

1. **작성일 기준** — 가격, 운영시간, 혜택, 쿠폰, 무료 취소·환불 조건처럼 바뀌는 정보(🔄)는 "작성일 기준 다시 확인" 체크가 된 것만 그대로 씁니다.
   체크가 안 됐으면 값 뒤에 `[작성일 기준 확인 필요]`를 붙입니다. 글 맨 위에 `YYYY년 M월 D일 기준` 문구를 넣습니다.
2. **직접 이용 여부** — "이용 안 함"이면 "써봤더니", "직접 묵어보니" 같은 후기 표현을 쓰지 않고 정보 정리 글로 씁니다.
3. **제휴 표시** — 제휴 링크가 하나라도 있으면 글 **맨 앞**에 경제적 이해관계 표시 문구를 넣습니다.
   (예: "이 글에는 제휴 링크가 포함되어 있으며, 링크로 예약하면 작성자가 수수료를 받을 수 있습니다.")
4. **단정 금지** — "최저가", "무제한", "누구나 가능", "모든 폰에서 됨", "노쇼핑", "무조건 이득" 같은 표현은 그대로 쓰지 않습니다.
   조건과 기준을 붙여 바꿉니다. (예: "무제한" → "하루 2GB 이후 저속 무제한")
5. **숨은 비용은 앞쪽에** — 리조트피, 도시세, 유류할증료, 가이드팁, 선택관광, 싱글차지, 장비·사진 추가 구매 등은 결론 전에, 글 앞부분에 둡니다.
6. **추천·비추천 둘 다** — 모든 글은 추천 대상과 비추천 대상을 함께 넣습니다. 비추천 대상이 비면 검토 경고를 띄웁니다.
7. **구체적으로** — "위치 좋아요" 대신 `역 도보 몇 분 / 공항 택시 몇 분`, "빨랐어요" 대신 `유튜브·지도·카톡·테더링 가능 여부`처럼 입력된 숫자·사실로 씁니다.
8. **핵심 질문으로 시작해서 끝내기** — 도입부는 카테고리 핵심 질문(또는 "독자가 가장 궁금해할 한 가지"), 결론은 그 질문에 대한 답입니다.

| 카테고리 | 핵심 질문 | 기본 CTA 문구 방향 |
| --- | --- | --- |
| eSIM | 내 폰에서 잘 터지고, 진짜 데이터가 충분한가? | 공항에서 급하게 사지 말고 가격 먼저 확인 |
| 숙소 | 이 가격에 위치·객실·시설이 실제로 괜찮은가? | 내 날짜 기준 가격 조회 |
| 투어 | 일정에 넣을 가치가 있고, 취소·안전 리스크는 없는가? | 마감 여부와 픽업 가능 지역부터 확인 |
| 패키지 | 광고 가격 말고 최종적으로 얼마가 드는가? | 포함·불포함과 추가 비용 확인 |
| 교통패스 | 내 동선에서 개별 결제보다 정말 이득인가? | 내 동선으로 본전 계산 후 구매 |

`verify.js`, `calc.js`, `checks.js`, `writer.js`는 나중에 테스트를 붙이기 쉽도록 **DOM에 의존하지 않게** 작성합니다.

## 입력 폼

- 첫 단계는 **글 종류 선택**입니다. `<select>` 목록 상자이고, 선택지는 `categories.js`의 `CATEGORIES`로 채웁니다. 고르기 전에는 다음 단계 탭·버튼을 막습니다.
- 공통 질문은 `COMMON_GROUPS`(글 방향 / 여행 정보 / 실제 경험 / 제휴 정보 / 추천·비추천 / 자료와 작성일)로 묶어 카드별로 보여 줍니다.
- 공통 질문은 `fields.js`, 카테고리별 질문은 `fields-<카테고리>.js`만 고칩니다. 화면 코드(`form.js`)는 고치지 않아도 됩니다.
- 질문은 묶음(`{ title, note, fields }`) 단위로 둡니다. `note`는 그 묶음에 해당하는 "특히 유의할 점"으로, 카드 위쪽에 보입니다.
- 입력칸 id는 `field-<common|카테고리>-<key>` 형식입니다. (예: `field-esim-device`) 폼 화면(`form.js`)은 목록을 보고 그리기만 합니다.
- 필드 정의 예:

```js
{
  key: "dailyLimit",
  label: "일일 제공량 이후 속도",
  help: "‘무제한’이라도 하루 몇 GB 뒤 느려지는지 꼭 적어 주세요.",
  example: "하루 2GB 이후 384kbps",
  type: "text",        // "text" | "textarea" | "date" | "select" | "checks"(여러 개 고르기)
  // select·checks는 options: ["문자열", ...] 또는 [{ value, label }, ...]
  // select에 placeholder가 있으면 빈 선택지("선택해 주세요")가 기본값입니다.
  volatile: true,      // 🔄 작성일 기준 확인이 필요한 정보
  required: true       // 비어 있으면 검토 경고
}
```

- `checks` 값만 배열(고른 글자들), 나머지 값은 모두 문자열입니다.
- 여러 개를 받는 칸(서브 키워드, 제휴 링크, 추천 대상 등)은 `textarea`에 **한 줄에 하나씩** 받고, 문자열로 저장합니다. 글을 만들 때 줄 단위로 나눕니다.
- `volatile: true` 필드에는 "🔄 작성일 기준 확인" 표시와 "○년 ○월 ○일 기준으로 다시 확인했어요" 체크가 붙습니다.
- 확인 기록은 `verified["<common|카테고리>.<key>"] = 확인한 작성일`로 저장합니다. 저장된 날짜가 지금 작성일과 같을 때만 확인된 것으로 봅니다. 그래서 작성일을 바꾸면 체크가 모두 풀립니다.
- 확인 현황은 **값을 입력한** 🔄 칸만 셉니다. 빈 칸은 확인할 것이 없으므로 빼요.
- 카테고리의 "특히 유의할 점"은 폼 위쪽 안내 상자로 보여 줍니다 (`categories.js`에서 가져옴).
- 여행 패키지는 첫 질문에서 유형(항공+호텔 / 자유여행 패키지 / 세미패키지 / 패키지여행)을 먼저 고릅니다.
- 카테고리를 바꿔도 공통 정보는 지우지 않습니다. 상세 폼 값은 카테고리별로 따로 보관합니다.

## 계산 규칙 (`calc.js`)

- 금액은 **원 단위 정수**로 계산합니다. 외화 입력은 사용자가 적은 환율로만 바꾸고, 환율을 지어내지 않습니다.
- 교통패스: `개별 요금 합계 - 패스 가격` = 절약(+) / 손해(-). 평균 개별 요금으로 "몇 번 타야 본전"인지 올림해서 보여 줍니다.
- 패키지: 광고가 + 유류할증료 + 가이드팁 + 선택관광 + 싱글차지 + 기타 → 실제 1인 총액, 인원 곱한 총액.
- 숙소: (객실가 + 세금 + 리조트피 + 도시세 + 조식·주차 등) ÷ 박수 → 1박 실제 가격.
- 입력이 비어 있는 항목은 0으로 치지 말고 "미입력"으로 표시해, 총액이 실제보다 싸 보이지 않게 합니다.

## 데이터 모델

```js
// localStorage 키: "travel-draft"
{
  version: 1,
  draft: {
    id: "t_<timestamp>",
    category: "",         // "" (아직 안 고름) | "esim" | "stay" | "tour" | "package" | "pass"
    common: {             // 모든 값은 문자열 (fields.js의 key 그대로)
      purpose: "search",  // "search" | "conversion" | "review" | "compare"
      mainKeyword: "", subKeywords: "",          // 서브 키워드는 한 줄에 하나
      readerQuestion: "",
      cta: "price",       // "price" | "discount" | "book" | "comment"
      destination: "", travelDate: "", people: "", travelStyle: "",
      usedMyself: "yes",  // "yes" | "no"
      experience: "", paidPrice: "", usedDate: "",
      affiliateLinks: "", discountCode: "",      // 링크는 한 줄에 하나
      recommendFor: "", notRecommendFor: "",     // 한 줄에 하나
      media: "",          // 한 줄에 하나, (공식)/(실제) 표시
      checkedDate: "2026-10-15"  // 작성일(확인일), 기본값 오늘. 글 맨 위 "기준" 문구에 사용
    },
    details: {            // 카테고리별 상세 폼 값 (fields-<카테고리>.js의 key 그대로)
      esim: { device: "", tethering: "", triedApps: ["유튜브"], ... },
      stay: { ... }, tour: { ... }, pass: { ... },
      package: { packageType: "", ... }  // "air-hotel" | "free" | "semi" | "full"
    },                    // 카테고리를 바꿔도 다른 카테고리 값은 지우지 않습니다.
    verified: {           // 작성일 기준 확인 기록: { "<common|카테고리>.<key>": "확인한 작성일" }
      "common.paidPrice": "2026-10-17"
    },
    createdAt: 1792022400000,
    updatedAt: 1792022400000
  }
}
// 테마: localStorage 키 "travel-theme" ("light" | "dark")
```

- 데이터 형식을 바꾸면 `version`을 올리고 `store.js`에 마이그레이션을 추가해 **작성 중인 글이 사라지지 않게** 합니다.

## Claude 자동 작성 (2차 목표)

- `instatoon/`과 같은 방식으로 claude.ai 아티팩트 기능(`window.claude`)을 씁니다. **API 키를 브라우저나 저장소에 두지 않습니다.**
- 요청문 = 글 작성 규칙 + 카테고리 상수 + 사용자 입력 + 계산 결과 + 검토 경고. 확인 안 된 변동 정보는 요청문에서도 `[작성일 기준 확인 필요]`로 넘깁니다.
- Claude 답은 화면에 넣을 때 항상 `textContent`/`value`를 씁니다.
- 방식이 정해지기 전에는 구현하지 않고 사용자에게 먼저 확인합니다.

## 디자인 가이드 (사이트 화면)

- 여행 느낌의 밝고 조용한 화면: 연한 하늘·모래색 배경, 강조색은 하나(예: `--accent` 바다색 계열)만.
- 🔄 변동 정보와 경고는 눈에 띄게, 하지만 빨간색 남발 없이 노란 배경 상자로.
- 테두리보다 배경색 차이로 영역을 나눕니다.
- 색상·간격은 `base.css`의 CSS 변수로만 지정하고, 하드코딩하지 않습니다.
- 다크 모드: `@media (prefers-color-scheme: dark)` + `[data-theme="dark"]`로 수동 전환 지원.
- 본문 폰트 크기는 16px 이상 (아이폰 Safari 입력 시 자동 확대 방지).
- 모든 화면 폭에서 한 번에 한 단계만 보이고, 단계 탭이나 이전/다음 버튼으로 이동합니다.
- 버튼에는 `aria-label`, 입력칸에는 `<label>`, 키보드로도 모든 기능을 쓸 수 있게 합니다.

## 보안

- 사용자가 입력한 문구를 화면에 넣을 때는 항상 `textContent`를 사용합니다. `innerHTML`에 사용자 텍스트를 넣지 않습니다.
- 글 초안 미리보기를 HTML로 보여 줄 때는 직접 만든 요소(`createElement`)로 그리고, 링크는 `http:`/`https:`만 허용합니다.
- 제휴 링크·할인코드는 브라우저에만 저장합니다. 외부 서비스로 보내는 기능은 사용자 확인 없이 추가하지 않습니다.

## 실행 & 확인

```bash
python3 -m http.server 8000   # 저장소 루트에서 → http://localhost:8000/travel/
```

자동 테스트는 아직 없습니다. 변경 후에는 다음을 직접 확인합니다.

- [ ] 글 종류를 고르기 전에는 다음 단계로 못 가고, 고르면 핵심 질문이 보이는가
- [ ] 여행 패키지를 고르면 패키지 유형 목록 상자가 나타나는가
- [ ] 폼 입력 → 새로고침해도 남아 있는가
- [ ] 카테고리를 바꾸면 상세 폼이 바뀌고, 공통 정보와 다른 카테고리 입력값은 그대로인가
- [ ] 체크박스(여러 개 고르기)가 새로고침 후에도 유지되는가
- [ ] 🔄 칸에 값을 넣으면 확인 현황에 나타나고, 체크하면 사라지는가
- [ ] 작성일을 바꾸면 확인 체크가 모두 풀리는가
- [ ] 🔄 항목을 확인 체크하지 않으면 초안에 `[작성일 기준 확인 필요]`가 붙는가 (6단계)
- [ ] "최저가", "무제한", "누구나 가능" 등을 입력하면 검토 경고가 뜨는가
- [ ] 제휴 링크가 있으면 초안 맨 앞에 제휴 표시 문구가 들어가는가
- [ ] 비추천 대상이 비면 경고가 뜨는가
- [ ] 교통패스 본전 계산, 패키지·숙소 총액이 맞는가 (빈 값은 "미입력")
- [ ] 직접 이용 "안 함"이면 후기 표현이 빠지는가
- [ ] 복사 버튼이 동작하는가
- [ ] 다크 모드와 모바일 폭(375px)에서 레이아웃이 깨지지 않는가
- [ ] 브라우저 콘솔에 에러가 없는가
